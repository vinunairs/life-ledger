# Technology-Currency Review: Family Life Ledger architecture (2026-10-05)

**Reviewer role:** technology-currency check, run 2026-10-05 against the live npm registry, nodejs.org release data, GitHub raw docs (supabase/supabase, github/docs, Fyrd/caniuse, mdn/browser-compat-data), the Supabase docs search API, and web search.
**Scope:** `ARCHITECTURE-SPINE.md` (Stack table and every named technology), `rpc-contracts.md`, `test-plan.md`, `offline-queue.md`, `data-model.md`.
**Access note:** supabase.com, webkit.org, caniuse.com and support.google.com were blocked by the egress proxy. Supabase facts come from the Supabase docs search API and the docs source on GitHub, which hold the same content. Free-plan quota numbers come from that plus third-party 2026 summaries, because the pricing page itself could not be fetched. Caniuse and MDN data come from their GitHub repositories.

## Verdict

The stack is current. Every pinned npm version matches today's latest stable release, and Postgres 17, pg_cron, pg_jsonschema, pgTAP, GitHub Pages and IndexedDB with a service worker are all live and suitable. Four things need fixing before M1:
1. Supabase's built-in email sender will not deliver the student's password-reset email.
2. The free-plan inactivity pause has no keep-alive.
3. The plan does not say that schema `ll` must be exposed and granted explicitly. Supabase is also changing grant defaults on 2026-10-30.
4. `age` 1.2.x and Node 22 are a version line behind.

Legend: **VERIFIED** = current and fits; **OUTDATED** = a newer line or version exists and should be adopted; **RISKY** = exists, but the design depends on a behaviour that needs a change or an explicit mitigation.

## Top findings (ranked)

1. **HIGH: S7.** The student's password-reset email will not be delivered: Supabase's built-in SMTP sends only to team members, at 2 emails/hour. Configure custom Auth SMTP (the Gmail app password works) and the redirect URL in M1 rather than deferring it to D-3.
2. **HIGH: S6.** Schema `ll` exposure and function grants are not specified. The schema must be exposed, and `revoke execute … from public` is needed on every `security definer` RPC, otherwise `anon` can call them. Supabase's switch to explicit grants (all projects from 2026-10-30) makes explicit grants mandatory in practice.
3. **MEDIUM: S3.** The 7-day inactivity pause stops the app and all pg_cron jobs. Add a daily keep-alive workflow in the ops repo, plus alerting on HTTP 540.
4. **MEDIUM: P3.** iOS storage eviction and separate storage for the PWA versus the Safari tab. Call `navigator.storage.persist()`, steer users to the installed icon, and warn when posts stay unsent for a long time. Background Sync is correctly not relied on.
5. **LOW–MEDIUM: V5/V6 and S4.** Move Node 22 (maintenance, EOL 2027-04-30) to Node 24 LTS. Move `age` 1.2.x to v1.3.2. Prune `cron.job_run_details` to protect the 500 MB budget. Decide on pg_jsonschema (it supports 2020-12) instead of leaving it as an assumption.

Confirmed current with no change needed: supabase-js 2.117.2, Supabase CLI 2.119.0, Playwright 1.63.0, Postgres 17, pgTAP via `supabase test db`, the `iat`-based session revocation, GitHub Pages subfolder deploy, and private-repo Actions quotas and behaviour.
