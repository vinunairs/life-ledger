- (decision) Paradigm: thin client over a policy-enforcing database (ports and adapters, Postgres = domain core). Prevents business rules split between browser and DB.
- (decision) All client mutations via security-definer RPCs; tables expose SELECT policies only. Ratifies psat-sprint pattern. Prevents ad-hoc writes bypassing status/visibility rules.
- (decision) Processor RPCs (ingest_draft, save_output, queue views) callable only by privileged roles (connector), revoked from anon/authenticated; they validate every payload regardless of caller.
- (decision) Entry fields stored as jsonb map field->{v, span, by} with an entry_type_fields registry driving gap computation. Rejected per-type tables: two ingest paths, duplicated gap logic.
- (decision) Status derived by one trigger function from gaps; confirmed only via confirm_entry RPC. entry_versions written by trigger, never by callers.
- (decision) Visibility: single SQL predicate ll.can_read(...) used by every RLS policy, storage policy and output-item filter. Effective entry visibility = narrower of type default and post visibility.
- (decision) Posts use client-generated UUID as primary key; create_post is insert-on-conflict-do-nothing -> offline queue idempotent. Queue in IndexedDB.
- (decision) Service worker caches the app shell (network-first) so posting works offline; deviates from psat-sprint (no cache) because PRD FR-9 requires offline.
- (decision) Q4: pg_cron for purge, status sweep and nightly accuracy check; digest email + weekly encrypted backup via scheduled GitHub Actions in a separate PRIVATE ops repo (public repo logs are public; public-repo schedules auto-disable after 60 days). Backup encrypted with age public key; private key only in owner's password manager.

- (decision) Timezone: store timestamptz UTC; schedules defined in America/New_York by hourly cron that checks local time (DST-safe), as psat-sprint does.
- (decision) Tests: pgTAP via supabase test db for RLS matrix and RPC contracts in CI on local Supabase; node unit tests; Playwright e2e against fake Supabase.
